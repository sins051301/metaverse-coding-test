# UI 설계 — 픽셀 라운지 + 코딩테스트 IDE

클릭해 볼 수 있는 목업: https://claude.ai/artifact/Htr11PW2b1iUMcFVjFbwXS (비공개 링크. 화면 전환, 맵 접기, 결과 예시 7가지 상태 토글 동작. hallmark 디자인 스킬로 제작(Squeeze 테마 기반, 바탕만 따뜻한 차콜), sloplint 검사 통과)

## 1. 화면 목록과 이동 흐름

```
라운지(전체 맵) ──[F] 빈 책상(노트북 켜기)──▶ 문제 선택 ──문제 클릭──▶ 풀이(분할 화면) ──[ESC] 일어나기──▶ 라운지
                                                    ▲                        │
                                                    └──── [← 문제 목록] ───────┘
      │                               │
      ├─[F] 남의 책상 / [관전]──▶ 관전(읽기 전용)
      └─[F] 페어 요청 → 주인 수락──▶ 페어(동시 편집 + 채팅)

게스트가 [코드 실행]·[제출]·[페어 요청]을 누르면 → 로그인 유도 모달 (지연 로그인)
```

| 화면 | 구성 | 데이터 |
|---|---|---|
| 라운지 (`/`, 1단계 구현) | 상단 바(로고, 접속자 수, 닉네임·게스트 표시·[로그인]) + 전체 맵. 빈 책상 근처에서 `[F] 책상에 앉기` 툴팁, 벽 위 전광판에 다른 사람의 SOLVED 자막 | 아바타 위치·상태는 STOMP |
| 문제 선택 (`/problems`) | 노트북 화면처럼 에디터와 같은 가장 깊은 차콜 타일에 문제 목록(번호, 제목, `Lv. n`). 위에 난이도 칩(전체 / Lv. n). 행을 누르면 풀이로. 라운지에서 책상에 앉으면 여기로 온다 | `GET /api/problems` |
| 풀이 | 프로그래머스 배치. `[맵 패널 280px ⇄ 활동 띠 48px]` 오른쪽에 문제 바(`← 문제 목록`, 제목, 난이도, `제출 내역` 버튼, 언어 선택) → `[지문 380px, 탭 없음] [에디터 / 아래 실행·채점 결과 260px]` → 하단 액션 바(`일어나기` … `초기화` `코드 실행` `제출 후 채점하기`) | 아래 표 |
| 관전 | 풀이와 같은 배치. 상단 배너 `OO님의 코드를 관전 중`, 언어 선택·실행·제출 숨김, 배너에 [페어 요청] | Yjs 문서 읽기 |
| 페어 | 풀이 배치 + 오른쪽 채팅 260px. 상대 커서·이름표·선택 영역 표시. 제출은 주인만(파트너 화면에서는 비활성) | Yjs + `y-monaco`, 채팅은 저장 안 함 |
| 로그인 유도 | 현재 화면 위 모달. "작성 중인 코드와 아바타 위치는 그대로 유지" 문구 | Google OAuth 팝업 |

### 풀이 화면이 쓰는 API 응답

| 영역 | 응답 | 표시 |
|---|---|---|
| 문제 바꾸기 (문제 선택 화면, `다른 문제` 팝오버는 2026-11-11 제거) | `GET /api/problems` → `ProblemSummaryResponse(id, title, level)` | 번호, 제목, `LV. n`, 로그인 유저가 푼 문제에 `DONE` 뱃지(푼 문제 API는 6단계) |
| 지문 탭 | `GET /api/problems/{id}` → `ProblemDetailResponse` | `title`, `level`, `timeLimitMs`·`memoryLimitMb` 칩, `description`(Markdown). 시그니처 한 줄은 지문 위에 두지 않음(2026-11-11 사용자 결정, 에디터 시작 코드에 이미 보임) |
| 에디터 | `starterCode` (`Map<Language, String>`) | 언어를 바꾸면 그 언어의 시작 코드. 작성 중 코드는 localStorage에 문제·언어별로 저장 |
| 터미널 | `POST /api/problems/{id}/runs` → `RunResponse(verdict, passedCount, totalCount, score, compileLog, tests)` | 아래 규칙 |

결과 패널 규칙 (프로그래머스 표기를 따름)
- `코드 실행` → 제목 "실행 결과". 예제마다 `테스트 n` 블록에 입력값, 기댓값, 실행 결과("테스트를 통과했어요." / "실행한 결괏값 2이(가) 기댓값 3과(와) 달라요.")와 시간·메모리
- `제출 후 채점하기` → 제목 "채점 결과". 맨 위에 점수를 크게(`62.5 / 100.0`, n개 중 m개 통과), 아래에 `테스트 n  통과 / 실패 (시간 초과)  0.11초, 38.2MB` 목록. 히든 테스트도 같은 줄 형식이라 입력이 드러나지 않음 (서버도 비워서 보냄, README 7장)
- 판정은 통과(초록)·실패(빨강) 두 색. WA/TLE/MLE/RE는 "실패 (런타임 에러)"처럼 글자로 구분
- `CE`는 "컴파일 에러가 나서 테스트를 실행하지 않았어요." + `compileLog`
- 네 가지 상태: 대기(무엇이 나올지 안내), 채점 중(스켈레톤), 서버 오류(코드는 남아 있다는 안내 + 다시 실행), 결과

## 2. 레이아웃 규칙

- 데스크톱 전용, 최소 폭 1280px. 그보다 좁으면 "넓은 화면에서 이용해 주세요" 안내
- 맵 패널 접기: ◀ 버튼으로 48px **활동 띠**로 접고 ▶로 펼친다. 접힘 여부는 localStorage에 기억
  - 활동 띠 내용: 접속자 수, 타이핑 중인 사람 수, 최근 SOLVED(★, 금색), 나에게 온 페어 요청(⇄, 깜빡임)
  - 접혀 있는 동안 Phaser는 렌더링을 멈추고(`game.loop.sleep()`), STOMP 수신은 계속해서 활동 띠만 갱신한다. IDE와 같이 켜 둘 때 자원을 아끼기 위함
- 패널 사이 경계는 드래그로 폭 조절(문제 280~520px, 터미널 높이 120px~화면의 60%)
- 단축키: `F` 상호작용, `ESC` 일어나기(에디터에 포커스가 있을 때는 Monaco가 ESC를 먼저 쓰므로 버튼 또는 포커스 밖에서만)

## 3. 테마 토큰

hallmark Squeeze 테마의 글꼴·둥근 모서리·버튼 규칙을 가져오고, 바탕색만 따뜻한 차콜로 바꾼 직접 조합. 컨셉은 "밤에 고양이들이 모여 코딩하는 아늑한 카페".
- 바뀐 과정: 흑연색 Console(각지고 차분함) → 사용자가 귀엽고 동글동글한 느낌을 원함 → Squeeze(초록 바탕) → 초록 바탕 위 흰 글씨는 가독성이 떨어진다는 피드백 → 바탕만 따뜻한 차콜(2026-11-05)

면의 규칙
- 바탕은 갈색기가 도는 **따뜻한 차콜**. 채도를 낮게 잡아 긴 지문과 코드를 오래 봐도 눈이 덜 피곤하다
- 한 단 밝은 차콜 = 타일(지도, 지문, 채팅), 한 단 어두운 차콜 = 움푹한 곳(실행·채점 결과), 더 밝은 차콜 = 떠 있는 것(문제 목록 팝오버, 로그인 모달)
- **에디터는 가장 깊은 차콜**이고 그림자가 있는 유일한 면이라 중요한 곳이 바로 보인다
- 크림색은 맵 위의 이름표·툴팁처럼 나무 바닥 위에서 읽혀야 하는 것에만
- **복숭아색은 누르는 것에만**: 제출 버튼, 선택된 칩·문제, 내 이름표, 페어 상대 커서. 복숭아색 글자나 면은 만들지 않음
- 판정은 통과(연두)·실패(분홍빛 빨강) 두 색. WA/TLE/MLE/RE/CE는 글자로 구분

| 토큰 | 값 (oklch) | 쓰는 곳 |
|---|---|---|
| `--color-paper` / `-2` / `-3` | `24% 0.012 60` / `29%` / `20%` | 바탕 / 타일 / 움푹한 곳 |
| `--color-raised` | `33% 0.016 60` | 팝오버, 모달 |
| `--color-ink` / `--color-muted` | `95% 0.012 85` / `75% 0.02 70` | 제목·본문(따뜻한 미색) / 보조 |
| `--color-card` | `17% 0.01 60` | 에디터 |
| `--color-tag` / `--color-tag-ink` | `95% 0.02 85` / `25% 0.02 60` | 맵 이름표·툴팁 |
| `--color-accent` / `-2` | `83% 0.115 56` / `74% 0.150 46` | 복숭아 버튼 / 눌렀을 때 |
| `--color-ok` / `--color-bad` | `80% 0.15 145` / `73% 0.15 22` | 통과 / 실패 |
| 모서리 | 패널·입력칸·표·팝오버·모달 6px / 버튼·칩·단축키 표시 알약형(999px) / 말풍선·툴팁·이름표 16px | 일하는 영역은 단단하게, 누르는 것과 고양이·사람 관련 요소만 둥글게 (2026-11-05 사용자 결정) |

에디터 문법 색은 어두운 바탕에서 읽히게 밝게 잡은 별도 토큰(`--code-keyword` 등). 맵 팔레트(`--map-*`, `--cat-*`)도 같은 차콜·나무·복숭아에서 뽑아 맵과 IDE가 한 공간으로 보이게 한다.

## 4. 캐릭터와 이펙트

아바타는 **동글한 픽셀 고양이**(10x10 도트, 머리가 큰 2등신). 털 무늬 5종: 치즈, 회색 줄무늬, 검정(금색 눈), 흰색, 샴. 책상에 앉으면 상반신만 보이고 앞발이 책상 위에, 노트북이 옆에 놓인다. 서서 걸을 때는 다리와 꼬리가 보이고 꼬리가 흔들린다.

| 상태 | 맵 | IDE |
|---|---|---|
| 타이핑 중 (마지막 입력 후 5초간) | 앞발이 번갈아 키보드를 두드리고, 머리 옆 말풍선의 점 3개가 돈다 | 에디터 머리에 `옆자리 고양이에게 작성 중으로 보여요` |
| 제출 AC | 내 머리 위 도트 글자 `SOLVED!`, 다른 고양이 머리 위 노란 별, 벽 전광판, 라운지 오른쪽 "방금 푼 고양이" 목록, 다른 사람 활동 띠에 별 | 점수 `100.0 / 100` |
| 제출 실패 | 시안 없음 (README에서 상세 미정) | 실패 테스트가 빨강 |
| 자리 비움 (5분 무입력) | 눈을 감고 머리 위에 `z`, 노트북 화면이 꺼짐 (`낮잠 중`) | — |
| 관전·페어 중 | 주인 책상 옆 표시 (미정) | 문제 바 아래 어두운 차콜 띠 배너 |

맵 애니메이션은 450ms마다 한 칸씩 끊어서 움직이고, `prefers-reduced-motion`이면 멈춘다. 고양이는 이 도트 설계를 기준으로 직접 그렸다(위에서 본 4방향 걷기가 있는 CC0 고양이가 없어서, 2026-11-11). 걷기는 초당 4칸. 앉은 자세·옆모습·뒷모습도 같은 10x10 템플릿 규칙으로 그리고, 털색은 팔레트만 바꾼다(`frontend/src/entities/avatar/lib/catSprite.ts`).

## 5. 기술 검토

### 맵 렌더링: Phaser 4.2.1 (확정, 2026-11-11)

| 후보 | 장점 | 단점 |
|---|---|---|
| **Phaser** (2D 게임 프레임워크) | 타일맵(Tiled JSON 로드), 스프라이트 애니메이션, 충돌, 키 입력, 카메라가 내장. 2D 탑다운 메타버스에 필요한 것이 대부분 있음 | 번들이 큼(약 1MB). React와 상태를 이벤트로 주고받는 연결 코드가 필요 |
| PixiJS (2D 렌더러) | 렌더링이 가볍고 빠름 | 타일맵·충돌·입력을 직접 만들어야 함 |
| Three.js (3D 렌더러) | 시각적 임팩트 | 작은 패널에서 원근·카메라 때문에 누가 뭘 하는지 식별이 어렵고, GPU를 계속 써서 IDE와 같이 켜면 무거움(README 1-1). 3D 모델·리깅 에셋을 구하기 어렵고 충돌·이동을 직접 구현 |
| Canvas 직접 | 의존성 없음 | 위 기능을 전부 직접 구현 |

2D 탑다운을 고른 이유
- 맵은 주인공이 아니라 코딩 옆에 두는 화면이라, 작게 줄여도 한눈에 보여야 한다
- 아바타 동기화 메시지가 `(x, y, 방향, 상태)`로 단순하고, "책상 근처면 [F]"가 타일 거리 비교로 끝난다
- CC0 에셋으로 통일된 스타일을 바로 맞출 수 있다

### 에셋

- 장식(화분·선반)은 Kenney Roguelike Indoors(CC0). 바닥·벽·책상·노트북은 이 팩에 없고 목업 팔레트와 맞춰야 해서 목업 도트대로 직접 그림. 출처는 `frontend/public/assets/CREDITS.md`
- 맵은 방 하나라 Tiled 대신 코드 데이터(`frontend/src/widgets/lounge-map/model/loungeMap.ts`)로 둠. 방이 늘면 Tiled 에디터로 충돌 레이어·책상 오브젝트를 지정해 JSON으로 옮김
- React 연결: 공통 레이아웃 라우트에 지도를 고정하고, React와 Phaser는 외부 저장소(`loungeStore`)로만 주고받음 (README 10장)
- 피할 것: 라이선스가 "무료이지만 재배포 금지"인 팩, ZEP·Gather 등 기존 서비스의 그림
